## 场景与成果

**案例文档** · 无需访问原内网入口或演示视频，可在本页了解场景与复用方法。

通过 Managed Session 编排多格式数据的读取、解析、计算、校验和回写，形成可回看的批处理任务。

本篇根据 showcase 资料整理，原案例贡献者：Qoder Agents 团队。内容介绍材料中的方案，不将其等同于已验证的生产部署或量化收益。

## 实现思路

原材料覆盖非实时、格式易变的数据任务。Agent 处理输入差异，执行环境完成实际计算，Skill 承载可复用的业务规则。

### 实践演练：从任务到验收

把三种供应商格式的合成订单统一成标准记录。输入格式会变化，但订单号、币种、金额和日期的输出契约固定。

以下是可复用的实现与验收建议，不代表演示站已公开这些后端能力，也不表示这些检查已经执行通过。演练使用合成或获授权输入；JSON 是应用侧记录示意，不是 QCA API 请求。

### 分步实现与交付物

#### 1. 建立任务清单

为输入文件或记录分配稳定标识与内容摘要，记录批次、来源和待处理状态。

#### 2. 隔离解析

按文件或小批次创建执行单元，先识别格式，再由业务规则提取标准字段。

#### 3. 逐条校验

检查必填字段、金额类型和日期格式；不合格记录进入失败队列，保留原输入引用。

#### 4. 幂等回写

使用记录键与版本写入结果，保存检查点；重跑只处理未完成或失败的输入。

### 输入输出记录示例

```json
{
  "batch_id": "demo-batch",
  "record_id": "order-001",
  "input_digest": "example-digest",
  "schema_version": "v1",
  "state": "validated",
  "output": {
    "currency": "CNY",
    "amount": 120
  }
}
```

将这份记录与产物或报告一起保存，用来回答“这份结果来自哪个输入、哪个版本”。凭证不写入记录。输入变化后应重新判断旧结果是否适用，不能静默复用。

## 复用建议
先定义每条记录的输入、输出和校验条件，再加入检查点、失败队列与幂等回写；仅对失败记录重试，保留错误原因。

### 关键取舍

批量大小影响吞吐、失败重试成本和定位难度。先按可独立校验的记录划分任务，再调并发；不要把整批成功与否绑定到一个长会话的最终回答。

### 故障与验收检查

| 检查条件 | 预期结果 |
|---|---|
| 某条记录无法解析 | 其他记录继续，失败项携带原因。 |
| 回写后进程中断 | 恢复后不产生第二份结果。 |
| 输入文件更新 | 生成新版本，旧结果仍可追溯。 |

为每个检查准备可重复输入，记录实际观察。验收时对照产物、状态或数值，不只阅读一段看似合理的解释；尚未验证的项目保留为待验收，不能按通过统计。

### 一组可直接核对的验收样例

以下为合成验收样例，展示预期行为，不是生产环境的实测结果。可先实现这一最小样例，再加入前面的故障条件。

```json
{
  "input": {
    "records": [
      {
        "id": "a",
        "amount": "12.50"
      },
      {
        "id": "b",
        "amount": "unknown"
      }
    ]
  },
  "expected": {
    "accepted": [
      {
        "id": "a",
        "amount": 12.5
      }
    ],
    "rejected": [
      {
        "id": "b",
        "reason": "invalid amount"
      }
    ]
  }
}
```

成功和失败记录都必须可定位。再次处理同一输入时，成功记录不新增副本，失败记录仍能被单独重试。
