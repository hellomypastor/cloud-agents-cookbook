## 场景与成果

**案例文档** · 无需访问原内网入口或演示视频，可在本页了解场景与复用方法。

围绕一部影片组织编剧、分镜、美术、演出、配乐与剪辑角色，探索跨会话内容生产协作。

本篇根据 showcase 资料整理，原案例贡献者：何傲。内容介绍材料中的方案，不将其等同于已验证的生产部署或量化收益。

## 实现思路

原案例描述以一个主协调角色连接六个专业角色。剧本、分镜、素材和成片是逐步依赖的交付物，角色之间需要共享版本与反馈。

### 实践演练：从任务到验收

以一段三十秒测试短片为目标，明确片长、风格和素材限制，让编剧、分镜、美术、演出、配乐与剪辑围绕共享产物协作。

以下是可复用的实现与验收建议，不代表演示站已公开这些后端能力，也不表示这些检查已经执行通过。演练使用合成或获授权输入；JSON 是应用侧记录示意，不是 QCA API 请求。

### 分步实现与交付物

#### 1. 冻结创作简报

记录主题、观众、时长、风格与禁用素材，主协调者负责处理范围变化。

#### 2. 定义角色交付

剧本输出场景，分镜输出镜头表，素材角色输出带标识的资源，剪辑使用明确版本。

#### 3. 沿依赖协作

可独立素材并行生成，依赖剧本的任务等待确认；返工更新关联镜头而非全部重做。

#### 4. 验收成片

核对时长、镜头连续性、音画和素材来源，汇总修改意见后由人确认最终版本。

### 输入输出记录示例

```json
{
  "production": "demo-short",
  "brief_version": "v1",
  "duration_seconds": 30,
  "shot_manifest": [
    {
      "shot": "s01",
      "script": "script-v2",
      "asset": "asset-v3"
    }
  ],
  "final_approval": "pending"
}
```

将这份记录与产物或报告一起保存，用来回答“这份结果来自哪个输入、哪个版本”。凭证不写入记录。输入变化后应重新判断旧结果是否适用，不能静默复用。

## 复用建议
先明确每个角色的交付格式和依赖，再设计返工路径。人类对最终版本做审批，避免多个会话各自修改不同版本的素材。

### 关键取舍

并行只适用于依赖已经明确的部分。角色越多，越需要共享镜头表和版本约定；否则节省的生成时间会消耗在返工与素材对齐上。

### 故障与验收检查

| 检查条件 | 预期结果 |
|---|---|
| 剧本中途改动 | 标记受影响镜头与素材，避免混用版本。 |
| 一个角色未按时交付 | 暴露依赖阻塞，而不是生成空白镜头。 |
| 素材缺少可用来源 | 替换或补齐来源后再进入成片。 |

为每个检查准备可重复输入，记录实际观察。验收时对照产物、状态或数值，不只阅读一段看似合理的解释；尚未验证的项目保留为待验收，不能按通过统计。

### 一组可直接核对的验收样例

以下为合成验收样例，展示预期行为，不是生产环境的实测结果。可先实现这一最小样例，再加入前面的故障条件。

```json
{
  "input": {
    "approved_script": "v2",
    "shot_assets": [
      {
        "shot": "s01",
        "script_version": "v1"
      }
    ]
  },
  "expected": {
    "ready_to_edit": false,
    "regenerate_or_review": [
      "s01"
    ]
  }
}
```

镜头素材存在不等于可以进入剪辑。先检查它是否符合已确认剧本，再决定复用、重做或请求导演确认。
