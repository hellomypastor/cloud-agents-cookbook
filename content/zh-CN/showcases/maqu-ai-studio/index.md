## 场景与成果

拍一部短片需要让剧本、分镜、画面和声音彼此衔接。马趣把复杂创作拆给专业角色，通过共享产物和版本把工作重新汇聚成一部成片。

围绕一部影片组织编剧、分镜、美术、演出、配乐与剪辑角色，探索跨会话内容生产协作。

本文根据何傲提供的 showcase 资料整理。流程图与分工表用于解释案例中的方法；后面的具体示例是复用建议，不作为生产运行的实测结论。

## 实现思路

### 一次任务如何流经产品

原案例描述以一个主协调角色连接六个专业角色。剧本、分镜、素材和成片是逐步依赖的交付物，角色之间需要共享版本与反馈。

```mermaid
flowchart LR
  N0["冻结创作简报"] --> N1
  N1["定义角色交付"] --> N2
  N2["沿依赖协作"] --> N3
  N3["验收成片"]
```

每个环节都需要把自己的输入与结果交给下一步。后续步骤据此继续工作，用户也能沿着这条链查看结果从哪里产生、在哪一步需要确认。

### 角色分工与权威事实

| 组成部分 | 在案例中的职责 |
|---|---|
| 协调者 | 简报、依赖与返工 |
| 专业角色 | 剧本、镜头、画面和声音 |
| 剪辑与审核 | 汇聚素材并确认成片 |

并行只适用于依赖已经明确的部分。角色越多，越需要共享镜头表和版本约定；否则节省的生成时间会消耗在返工与素材对齐上。

### 沿着一个具体任务展开

以一段三十秒测试短片为目标，明确片长、风格和素材限制，让编剧、分镜、美术、演出、配乐与剪辑围绕共享产物协作。

1. **冻结创作简报**：记录主题、观众、时长、风格与禁用素材，主协调者负责处理范围变化。
2. **定义角色交付**：剧本输出场景，分镜输出镜头表，素材角色输出带标识的资源，剪辑使用明确版本。
3. **沿依赖协作**：可独立素材并行生成，依赖剧本的任务等待确认；返工更新关联镜头而非全部重做。
4. **验收成片**：核对时长、镜头连续性、音画和素材来源，汇总修改意见后由人确认最终版本。

这条流程的交付物需要保留过程中使用的依据。某一步缺少数据或执行失败时，应让状态继续可见，避免后续环节把它当作已经完成的结果。

### 让结果可以被核对

下面用一组合成数据说明预期交付。它是应用侧的说明样例，不是 QCA API 请求，也不是生产记录。

```json
{
  "input": {
    "approved_script": "v2",
    "shot_assets": [
      {
        "shot": "s01",
        "script_version": "v1"
      }
    ]
  },
  "expected": {
    "ready_to_edit": false,
    "regenerate_or_review": [
      "s01"
    ]
  }
}
```

镜头素材存在不等于可以进入剪辑。先检查它是否符合已确认剧本，再决定复用、重做或请求导演确认。

## 复用建议

落地时可以先复现上面的一个任务，用已知输入核对交付结果，再补齐下面这些失败或歧义场景。通过后再扩大任务范围。

| 失败或歧义场景 | 需要保留的行为 |
|---|---|
| 剧本中途改动 | 标记受影响镜头与素材，避免混用版本。 |
| 一个角色未按时交付 | 暴露依赖阻塞，而不是生成空白镜头。 |
| 素材缺少可用来源 | 替换或补齐来源后再进入成片。 |
