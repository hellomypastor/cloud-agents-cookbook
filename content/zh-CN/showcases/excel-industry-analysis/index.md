## 场景与成果

同一个销售问题，换一份工作簿就可能需要重新解释字段、单位和统计口径。行业 Excel 分析的任务，是让业务人员确认这些差异后，继续用自然语言提问。

以字段映射和问题分析两个角色理解陌生表格，将自然语言问题转成受约束的计算配置。

本文根据阿米提供的 showcase 资料整理。流程图与分工表用于解释案例中的方法；后面的具体示例是复用建议，不作为生产运行的实测结论。

## 实现思路

### 一次任务如何流经产品

Mapper 识别字段与业务口径，Analyzer 生成聚合配置，确定性引擎执行和校验。人工确认字段映射后，再将该映射复用于后续问题。

```mermaid
flowchart LR
  N0["识别表结构"] --> N1
  N1["确认映射"] --> N2
  N2["编译问题"] --> N3
  N3["执行并核对"]
```

每个环节都需要把自己的输入与结果交给下一步。后续步骤据此继续工作，用户也能沿着这条链查看结果从哪里产生、在哪一步需要确认。

### 角色分工与权威事实

| 组成部分 | 在案例中的职责 |
|---|---|
| Mapper | 字段、单位与口径映射 |
| Analyzer | 问题到受约束聚合配置 |
| 计算引擎 | 确定性计算与结果校验 |

双 Agent 的价值在于分离字段理解和问题编译，不是让两个模型重复算数。字段稳定的小表可以先用一个角色；只有复用映射、多人维护或口径复杂时，再拆开职责。

### 沿着一个具体任务展开

用一份合成的销售工作簿回答“各地区本月净销售额是多少”。表里同时存在金额、退款、地区别名和重复订单，重点是把口径确认与数值计算分开。

1. **识别表结构**：读取工作表名称、列名和少量样本，识别订单粒度；不能仅凭列名把“金额”认定为净收入。
2. **确认映射**：Mapper 提议标准字段、单位与缺失值策略，把不确定映射交给使用者确认，再冻结映射版本。
3. **编译问题**：Analyzer 输出维度、指标、筛选与聚合配置，执行器只接受允许的字段和运算。
4. **执行并核对**：确定性引擎过滤日期、去重和计算，返回结果与被排除行数；报告引用实际结果，不让模型重新心算。

这条流程的交付物需要保留过程中使用的依据。某一步缺少数据或执行失败时，应让状态继续可见，避免后续环节把它当作已经完成的结果。

### 让结果可以被核对

下面用一组合成数据说明预期交付。它是应用侧的说明样例，不是 QCA API 请求，也不是生产记录。

```json
{
  "input": {
    "rows": [
      {
        "order": "a",
        "region": "east",
        "gross": 100,
        "refund": 20
      },
      {
        "order": "b",
        "region": "east",
        "gross": 50,
        "refund": 0
      }
    ]
  },
  "expected": {
    "region": "east",
    "net_amount": 130
  }
}
```

先按订单去重，再逐行计算金额减退款，最后按地区求和。本例刻意保持单位一致；加入不同币种后应拒绝直接求和。

## 复用建议

落地时可以先复现上面的一个任务，用已知输入核对交付结果，再补齐下面这些失败或歧义场景。通过后再扩大任务范围。

| 失败或歧义场景 | 需要保留的行为 |
|---|---|
| 同名金额列分别含税与未税 | 阻止自动合并，要求确认计算口径。 |
| 重复订单与空地区 | 输出去重及缺失记录数量，与人工参考表核对。 |
| 不支持的自然语言指标 | 明确拒绝或补问，不生成看似正确的数值。 |
